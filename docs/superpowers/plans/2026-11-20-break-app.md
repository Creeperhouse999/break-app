# Break App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A light Windows tray app that runs user-defined break rules ("every X, for Y") with HiSync-style notifications, window/fullscreen breaks, a best-effort input lock, smart pausing, idle detection, stats, and a large but well-organized settings window.

**Architecture:** Two projects. `BreakApp.Core` (plain `net10.0`, no WPF) holds every decision: models, settings persistence, presets, the scheduler state machine, pause evaluation, commitment rules, history and stats. It takes an injected clock and plain input snapshots, so it's fully unit-tested. `BreakApp` (`net10.0-windows10.0.19041.0`, WPF + WinForms tray) is a thin shell. It gathers OS signals (idle, gamepad, media, mic/cam, notification state), ticks the scheduler once per second, and renders what it says.

**Tech Stack:** C# / .NET 10, WPF, `System.Windows.Forms.NotifyIcon` (tray), `System.Text.Json`, xUnit. Win32 via P/Invoke (`SetWindowsHookEx`, `GetLastInputInfo`, `XInputGetState`, `SHQueryUserNotificationState`, `RegisterHotKey`, `DwmSetWindowAttribute`). WinRT `GlobalSystemMediaTransportControlsSessionManager` for media playback. No other NuGet packages besides xUnit.

**Spec:** `docs/superpowers/specs/2026-11-20-break-app-design.md`

**SDK:** `%LOCALAPPDATA%\dotnet10\dotnet.exe` (user-local .NET 10 SDK). Every `dotnet` command below means that exe.

## Global Constraints

- Windows 10/11, portable, never requires admin. Autostart via `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`.
- Idle RAM target < 60 MB; zero work between 1 s ticks besides one timer.
- English UI only.
- No Windows toasts anywhere; all notifications use the app's own card (spec §6a).
- Every setting in the model has a UI control with a one-line description (spec anti-goal "settings in file but not in UI").
- Storage: `%AppData%\BreakApp\settings.json`, `%AppData%\BreakApp\history.jsonl`.
- Single instance (named mutex `BreakApp.SingleInstance`).
- Input lock hooks must be removed on break end, app exit, and unhandled exception.

## Review Focus

1. **Corrupt or old settings.json:** the app must start with defaults (backing up the bad file as `settings.bad.json`), never crash. Test in Task 1.
2. **PC sleeps or the clock jumps (sleep, hibernate, manual time change):** no burst of breaks, no double-fire for one due time, negative deltas ignored. Test in Task 4.
3. **Rule with odd values (interval shorter than duration, 0, huge, lead time longer than interval):** values clamped, scheduler never fires every tick. Tests in Tasks 1 and 3.
4. **All rules disabled, or the only rule outside its active hours:** the tray shows "No upcoming breaks" and nothing crashes. Test in Task 3.
5. **Monitors unplugged or changed between breaks:** break windows are created per current screen at show time, never cached. Covered in Task 10 (enumerate screens at show time).

    - `IReadOnlyList<SchedulerEvent> Tick(ActivitySnapshot activity, PauseState pause)`

    - `bool Postpone(Guid ruleId)` (false if not allowed or max reached)
    - `void SkipNext(Guid ruleId)` / `void TakeNow(Guid ruleId)` (next Tick emits BreakDueEvent)

- Semantics (spec §5, §8, §10):
  - Per rule: `Elapsed`, `Warned`, `PostponeCount`, `SkipNextFlag`. Due when `Elapsed >= Interval`. `TimeUntil = Interval - Elapsed`.
  - ActiveTime: `Elapsed += delta` while `IdleFor < Threshold`. ClockTime: always. ClockAligned: due at local-midnight + k·Interval; `TimeUntil` = to next point; `Elapsed` derived from that.
  - Warning: once per cycle when `0 < TimeUntil <= Warning.LeadTime` and `Warning.ShowNotification || Warning.PlaySound`.
  - While `InBreak` or paused, no rule's Elapsed advances and nothing fires.
  - Disabled rules and rules outside `ActiveWindows` don't count or fire.
  - Postpone: `Elapsed = Interval - PostponeLength`, `PostponeCount++`, `Warned=false`. Count resets in `BreakFinished`.
  - SkipNext: when due → emit `RuleSatisfiedEvent(rule, Skipped)` and reset instead of `BreakDueEvent`.
  - `BreakFinished`: reset that rule (`Elapsed=0`, `Warned=false`, `PostponeCount=0`); `Collision=ResetAll` → reset every rule.

### Task 4: Scheduler: idle satisfaction, sleep gaps, collisions, pause reset

**Files:**
- Modify: `src/BreakApp.Core/Scheduling/Scheduler.cs`
- Test: `tests/BreakApp.Core.Tests/SchedulerIdleCollisionTests.cs`

**Interfaces:** same as Task 3 (no new public API).

Semantics:
- **Natural breaks** (if `Idle.NaturalBreaks`): when `IdleFor >= max(Threshold, rule.Duration)` and not yet satisfied in this idle stretch → emit `RuleSatisfiedEvent(rule, SatisfiedByIdle)`, reset the rule, mark it satisfied until IdleFor drops below Threshold. Applies to ActiveTime and ClockTime. ClockAligned: a boundary passed while idle counts as satisfied once `IdleFor >= Duration`; if the user returns with less, it fires on return if still within the same interval, otherwise it's dropped (logged as satisfied).
- **Tick delta:** `delta = now - lastTick`. Negative → treat as 0 and resync. `delta > 30 s` = sleep/clock jump → handled as an idle stretch of length `delta` (natural break rules above, with `IdleFor = delta`), then counting resumes. A rule overdue after the gap fires at most once.
- **Collision:** when ≥1 rule is due in a tick, every other enabled rule with `TimeUntil <= CollisionWindow` joins the group. BiggerWins → emit one `BreakDueEvent(primary, merged)`; primary = max by (Duration, Lock rank, Style rank); merged rules reset with outcome `MergedIntoBigger` once the primary finishes. Sequential → one `BreakDueEvent` per rule, shortest first, `Merged=[]`; the shell queues them. ResetAll → like BiggerWins, plus `BreakFinished` resets all.
- **Pause Reset policy:** on the transition paused→unpaused with `TimersDuringPause=Reset`, every rule resets.
